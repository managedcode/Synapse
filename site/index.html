01The problem How engines work today

Every token fires the whole model.

LLM engines run every block for every token and keep every weight in memory. A wall of compute, whether the token needs it or not.

02The idea Next

A wave, not a wall.

A fly's brain sends a signal through only the few regions it needs (FlyWire connectome). Synapse does the same with a model: dense attention always runs, the model's own router picks the expert, and a region is skipped only with proof.

03Memory Built · layer drop

Cold regions stay on disk.

A layer a profile drops never loads: its weights stay on disk and it gets no KV cache. Its quality cost is measured before it is dropped.

240 MiBper dropped layer, Qwen2.5-7B

04Scale Built · wiring in next

One model. Several machines.

Regions run on different machines. Only the hidden state travels between them.

Not there yet. We say so.

  • Prompt processingThe local 0.5B first-token charts show the long-prompt gap. For 7B, Synapse records 16.9–17.3 s to its first token; llama.cpp records 10.8–11.2 s of native prompt evaluation. Those 7B phase definitions differ, so they do not establish a first-token speedup.
  • Q4 writing speedThe 7B in Q4_K_M uses less peak RSS than llama.cpp in these two rounds. Synapse reports 17.4–18.2 decode tokens/s; llama.cpp reports 27.0–29.3 native-evaluation tokens/s. The phase definitions differ; faster Q4 kernels are next.
  • Past 32kThe 7B-1M model and head size 128 kernels run now. Windows past 32k have not been measured yet.
  • Smart context on CPU onlyReading only the relevant KV pages costs +3.4% perplexity while reading 30% of an 8k context. The GPU kernels are next.
  • CUDA untestedMetal runs. The CUDA backend is written but has not run on an NVIDIA GPU yet; it rejects Q4_K_M files for now.
  • One familyOnly Qwen2 runs today. More model families and MoE expert paging are next.

Why Synapse

Built for .NET, from the kernels up.

C#

Pure C#, no Python

.NET 10 owns the portable path. Rust takes a kernel only after profiling proves it is worth it.

⌂

Local first

One process, no server, no network. The cluster is an option, never a requirement.

=

Same answer as llama.cpp

Qwen2.5 runs fully in C#. In the benchmark it writes exactly the same tokens as llama.cpp.

≈

Small drafts, exact answer

A 0.5B model drafts tokens and the 7B checks them in one pass. The answer stays exactly the 7B's, 1.35× faster on chat text.

!

Fails loudly

Model math, precision and cache formats are explicit. An unsupported fast path fails instead of guessing.

✓

Verified and cross-platform

Model downloads are verified. Tests and benchmarks run on macOS, Linux and Windows.

Get started

Fetch. Prepare. Generate.

1 · Fetch the smoke-test model
dotnet run --project src/Synapse.Cli -- model fetch --set smoke
2 · Prepare the model once
dotnet run --project src/Synapse.Cli --configuration Release -- model compile --source artifacts/models/qwen2.5-0.5b-instruct-q8_0/qwen2.5-0.5b-instruct-q8_0.gguf --output artifacts/models/qwen2.5-0.5b-instruct-q8_0/qwen2.5-0.5b-instruct-q8_0.synapse
3 · Generate 8 tokens from .synapse
dotnet run --project src/Synapse.Cli --configuration Release -- generate \
  --model artifacts/models/qwen2.5-0.5b-instruct-q8_0/qwen2.5-0.5b-instruct-q8_0.synapse \
  --tokens 785,6722,315,9625,374 --max-tokens 8

Needs .NET SDK 10.0.401 and Rust 1.98.1. Every command is in AGENTS.md.
